## Открытые вопросы (что ждём от пользователя)

1. **Фьюзы** — прочитать в PROGISP (кнопка `...` / вкладка CONFIG → Read), ничего не записывая.
   - младший `0x62` → внутренний RC 8 МГц / 8 = 1 МГц, кварц не используется → менять low на `0xFF`;
   - младший `0xFF`/`0xF7`/`0xDE`… → работает от кварца (ожидается у Pro Mini).
2. **Частота** — зашить `.pio/build/clocktest/firmware.hex`, засечь 30 переключений D13:
   30 с → 16 МГц (ожидается), 60 с → 8 МГц, 480 с → 1 МГц (внутренний RC с CKDIV8).
3. **INT** — нужен ли свободный GPIO на основном модуле (на SV5 линии нет).
   Пока работаем опросом.

## План стенда (порядок важен)

Цель: проверить модуль клавиатуры **до** подключения к STM32 — через его UART.

1. ~~Питание модуля: измерить VCC~~ — сделано 2026-10-04: VCC = 5 В.
2. **Программатор** USBasp → Pro Mini: 1 MOSI → 11, 9 MISO → 12, 7 SCK → 13, 5 RST → RST,
   GND → GND, 2 VCC → VCC (можно, плата 5 В). Питать **от одного источника**: либо от
   программатора, либо от RAW — не одновременно. Прочитать фьюзы → п. 1.
   Клавиатура может оставаться подключённой, кнопки при прошивке не нажимать.
3. **`clocktest`** → частота (п. 2).
4. **USB-UART переходник** (уровень 5 В) на торцевую гребёнку: TX → RXI, RX → TXO, GND.
5. **`uarttest`** (38400): в терминале строка `UART test, F_CPU=… Vcc=…`, затем на каждое
   нажатие — пакет в HEX с CRC и расшифровка. Проверить: все 16 кнопок, группа с `#`,
   сброс `*`, предел 16 цифр, пауза 10 с, A–D сразу.
6. **STM32** через SV5: GND, +5V → RAW (или VCC) модуля, SDA PB7 → A4, SCL PB6 → A5,
   подтяжки 4,7 кОм от A4 и A5 к VCC модуля (5 В). Прошивка `ATmega328P`
   (не `uarttest`: тот сам подтверждает пакеты). На STM32: I2C1 open-drain, без
   внутренних подтяжек.

## Решения

### Аппаратная часть

- **Распиновка клавиатуры.** Шлейф 1..8 слева направо, лицевая сторона, шлейф вниз:
  1–4 строки сверху вниз, 5–8 столбцы слева направо. Подтверждено прозвонкой 2026-10-03
  («1» = 1+5, «D» = 4+8).
  Раскладка: `1 2 3 A / 4 5 6 B / 7 8 9 C / * 0 # D`.
- **Подключение к ATmega:** строки → PD4..PD7 (D4–D7), столбцы → PB0..PB3 (D8–D11),
  INT → PD2, SDA → PC4, SCL → PC5. PD0/PD1 свободны под отладочный UART.
- **ISP (USBasp):** MOSI PB3, MISO PB4, SCK PB5, RESET PC6. Разъём USBasp 10 выв.:
  1 MOSI, 2 VCC, 4/6/8/10 GND, 5 RST, 7 SCK, 9 MISO, 3 не подключать.
  6 выв.: 1 MISO, 2 VCC, 3 SCK, 4 MOSI, 5 RST, 6 GND.
  ATmega328P DIP-28: MOSI 17, MISO 18, SCK 19, RESET 1, VCC 7 (+AVCC 20), GND 8/22.
  TQFP-32: MOSI 15, MISO 16, SCK 17, RESET 29, VCC 4/6 (+AVCC 18), GND 3/5/21.
  PB3 — это и столбец 4 клавиатуры, PB5 — светодиод D13: при прошивке кнопки не нажимать.
- **Плата — Arduino Pro Mini (клон).** Отдельного разъёма ISP нет, программатор проводами:
  USBasp 1 MOSI → **11**, 9 MISO → **12**, 7 SCK → **13**, 5 RST → **RST**, GND → **GND**,
  2 VCC → **VCC** только если VCC платы = 5 В. Все эти контакты в одном длинном ряду
  `RAW GND RST VCC A3 A2 A1 A0 13 12 11 10`; другой ряд `TXO RXI RST GND 2 3 4 5 6 7 8 9`.
  - Питание извне — на **RAW** (через стабилизатор); **VCC** — выход стабилизатора.
  - UART — торцевая гребёнка `BLK(GND) GND VCC RXI TXO GRN(DTR)` под переходник FTDI-типа:
    TX переходника → RXI, RX → TXO, GND. GRN (DTR) сбрасывает плату при открытии порта.
  - **SDA/SCL (A4/A5) — на внутренних площадках** рядом с A6/A7, не на краях: паять провода.
  - Подтяжек I²C на Pro Mini нет → внешние 4,7 кОм.
  - Прошивка по ISP с Chip Erase стирает загрузчик Arduino — он не нужен.
  - Стандартные пары Pro Mini: 5 В ↔ 16 МГц, 3,3 В ↔ 8 МГц; фьюзы у таких плат
    обычно на внешний резонатор (low 0xFF) — подтвердить чтением.
- **Опрос матрицы:** активная строка = выход 0, неактивные = вход без подтяжки (Z),
  столбцы — вход с внутренней подтяжкой. Z на неактивных строках исключает КЗ
  выходов при двух нажатых кнопках в одном столбце.
- **INT — открытый сток**, активный низкий: ATmega только тянет к 0 или отпускает.
  Подтяжка на стороне STM32 к 3,3 В. Поэтому уровни INT безопасны при любом питании ATmega.
- **Встроенные подтяжки ATmega на SDA/SCL выключены** (Wire включает их к 5 В).
  Подтяжки шины — снаружи.
- **Уровни I²C (поправка к веб-чату).** В веб-чате было сказано, что ATmega читает
  3,3 В как единицу (порог ~3,0 В). Для ножек TWI это неверно: у ATmega328P
  V_IH = 0,7·Vcc, при 5 В это 3,5 В. Значит, при питании ATmega от 5 В подтяжки к 3,3 В
  недостаточно → преобразователь уровней. STM32F407 ножки I2C1 — FT (5 В допустимо
  при включённом питании STM32; без питания 5 В на шину не подавать).
  *Пределы FT-ножек приводились по памяти; datasheet `Cowork_MyStock/datasheets/stm32f407.pdf`
  (txt-копия в `datasheets/txt/`) — сверить при проектировании платы.*
  *Datasheet ATmega328P — в проекте: `docs/atmega328p.PDF` (полный) и `docs/atmega328p_.PDF`.*
- **Решение по уровням (2026-10-04, ATmega на 5 В):** подтяжки SDA/SCL 4,7 кОм к **5 В
  на стороне модуля**, без преобразователя. *Почему:* ATmega нужна единица ≥ 3,5 В,
  PB6/PB7 STM32 — FT (до VDD+4 В), а модуль питается от +5V разъёма SV5 основного модуля,
  то есть обе стороны включаются вместе. Условие: на STM32 I2C1 в open-drain без
  внутренних подтяжек. Для серийного изделия остаётся рекомендация ставить PCA9306/BSS138.
- **Сторожевой таймер** 500 мс.

### Протокол (файл `include/protocol.h`, общий для ATmega и STM32)

- **I²C-адрес** ATmega `0x20` (7 бит). ATmega — ведомый, STM32 — ведущий.
- **Контрольная сумма** — CRC-8, полином 0x07, init 0 (SMBus PEC), считается по байту
  адреса (addr<<1|R/W) и всем байтам пакета. Простая сумма отвергнута: не ловит
  перестановку байтов и пропуск нулевого байта.
- **Пакет ATmega → STM32:** `[тип][seq][N][данные N][CRC]`. STM32 читает **21 байт за одну
  транзакцию** и разбирает по N (каждое чтение отдаёт пакет с начала, по частям нельзя).
- **Чтение не удаляет пакет.** Удаляет только `ACK [seq]`. При ошибке CRC STM32
  перечитывает. seq 1..255 (0 — только у пакета «нет событий»): защита от двойной
  обработки при потерянном ACK.
- **Команды STM32 → ATmega** тоже с CRC; при неверной CRC команда игнорируется,
  ставится флаг `KBD_FLAG_CRC_ERR`.
- **Типы пакетов:** 0x00 нет событий; 0x01 клавиша (бит 7 = нажата, ASCII);
  0x02 группа `[причина][символы]`; 0x03 отмена `[причина]`; 0x10 статус
  `[флаги][в очереди][версия ПО]`.
- **Команды:** 0x01 ACK, 0x02 CONFIG `[maxLen][endKey][clearKey][timeout с][flags]`,
  0x03 STATUS, 0x04 CLEAR_FLAGS, 0x05 RESET.
- **Очередь** 8 пакетов; переполнение → флаг `KBD_FLAG_OVERFLOW`.

### Логика ввода

- **Конец ввода — клавиша `#`** (основной признак). Пауза и предельная длина —
  дополнительные. Одна пауза отвергнута: не различает «ввёл одну цифру и закончил»
  и «задумался».
- **Раскладка вместо режимов:** цифры копятся в буфере; `#` отправляет (одна цифра + `#`
  = группа длины 1); `*` стирает; A–D уходят сразу одиночными пакетами.
- **Причина завершения** в первом байте данных: 1 `#`, 2 предельная длина, 3 пауза, 4 `*`.
- **Пауза по умолчанию 10 с, недобранный ввод стирается** (пакет 0x03 с причиной 3),
  а не отправляется — чтобы брошенные цифры не ушли как попытка входа. Флаг
  `KBD_CFG_TIMEOUT_SEND` меняет поведение (для ввода чисел в меню).
- **Предельная длина** по умолчанию 16.
- **Отпускание** функциональных клавиш по умолчанию не шлётся (флаг `KBD_CFG_KEY_RELEASE`).
- **Пароль сравнивает STM32**, не ATmega: эталон в доступной снаружи панели не хранить.
  ATmega после отправки затирает буфер. CRC защищает от помех, не от подслушивания шлейфа.
- **Пошаговый режим цифр** (для навигации в меню) — отложен, добавить командой при необходимости.

### Среда разработки

- **Где ведётся работа:** только Claude Code в VS Code (веб-чат закрыт с 2026-10-03).
- **Репозиторий:** https://github.com/granel2/atm328p_keyboard, ветка `main`.
  В git не идут `.pio/`, `.cache/` (индекс clangd), `compile_commands.json`.
- PlatformIO + Arduino (ядро MiniCore), `board = ATmega328P`.
- Окружения: `ATmega328P` — рабочая прошивка; `clocktest` — тест частоты/питания
  (`src/clocktest.cpp`, 9600); `uarttest` — тест модуля без STM32 через UART 38400
  (`-D KBD_UART_TEST`: печать пакетов с CRC, пакеты подтверждаются сами — с STM32
  не использовать).
- Прошивка через **PROGISP**: `Load Flash` → `.pio\build\<env>\firmware.hex` → `Auto`.
  `upload_protocol = usbasp`, `-B 32` в ini есть, но avrdude под Windows может не видеть
  программатор с драйвером PROGISP (нужен Zadig/libusb-win32, может сломать PROGISP).
- **Фьюзы не трогать** (Program Fuse, Lock Chip, «Set Fuses»/«Burn Bootloader» в PIO),
  пока не прочитаны текущие значения.
- IntelliSense: clangd + `compile_commands.json` (`pio run -t compiledb` после изменений
  `platformio.ini` или новых файлов), `.clangd` убирает gcc-флаги, MS IntelliSense выключен.
